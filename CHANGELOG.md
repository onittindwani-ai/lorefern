# Changelog

## 1.0.2 (2026-11-27)

Documentation and demo label updates.

## 1.0.1 (2026-11-25)

Security and install hardening. No new screens, but every read and write path is stricter.

- **Visibility.** A document, transcript or file with no tag, or an unknown one, is now owner only instead of company wide. A document's own header, its folder's tag and the source's tag are combined and the narrowest wins. Meeting transcripts now read their own `Visibility` header. A retag can no longer widen a row, and it clears reviews, process evidence and stored answers that may quote what became restricted.
- **Deleted and unshared documents leave the index.** A finished read removes what it no longer sees. One bad file no longer stops a read. Folder sources read only their own folder; Drive and Notion sources read only the folders or pages in their path, and never trashed files.
- **Change routes** check the record's tag first and answer 404 like a missing record. The integrations page, settings, audit log and event payloads no longer show what a person may not see.
- **Demo shortcuts.** The demo password, the example accounts and the reset route work only in a real demo (no owner hash), and the reset refuses while a real source exists.
- **Sign in.** One cleaned email for the throttle and the lookup, a limit per address and per account, unknown accounts cost the same time as known ones.
- **Install.** Alembic and the worker read the same settings as the API. The app and the worker refuse an example secret, a placeholder company name or sender on a live install, and plain text mail to another host. Mail uses verified TLS. Company name, sender and time zone are settings. `.env.example` lists every setting and a test keeps the docs in step. The backup script copies the knowledge volume and refuses an empty dump. Docker compose pins Postgres, and the web service has a health check.
- **Web.** An error page and a not found page. The Sources page sets what untagged documents get, and the meeting import asks for a tag.
- **Docs.** Windows (WSL 2) and Ubuntu notes, the Docker prerequisites, honest CI wording, a private way to report a vulnerability.
- **Second review: tags.** The narrowest tag of a document, its folders and its source now really wins (a file marked `company` inside a `people` folder is `people`; nested folders can only narrow; `visibility: inherit` takes the folder's tag; the shipped templates say `inherit`; the folder check warns `wider_than_folder`). When a meeting's tag changes, its tasks and decisions follow it, and narrowing clears weekly reviews, process evidence and stored answers; a re-imported transcript can keep or narrow its tag, never widen it, and a caller who cannot see the existing row learns nothing from the answer. Task and decision lists no longer return the title of a meeting the person cannot open, and the meeting page filters its tasks and decisions by tag.
- **Second review: reads that stopped early.** A Drive or Notion read that hit a limit, or could not read a file or page (a rate limit, a server error), removes nothing from the index and the Sources page says so. A Drive file is size checked while it is read, and Notion pages are read in every block page.
- **Second review: smaller leaks and limits.** The audit log hides entries about a source the person cannot see. Pending approvals are counted and listed only for people who may see their tasks. The folder page counts only what the person sees and works when the source has its own path. With `PROCESS_WORDING=model` only company wide lines are sent. Search ranking uses the statistics of the passages a person may see, memory stays flat as the index grows, the word weight cache is cleared by a retag, and the documents filter runs before the limit. Hashes and the member list are out of the settings text, and an email longer than the shared audit column (80) is refused at start. An empty index no longer fails the first question on a new install.
- **Second review: deploy and docs.** A failed migration stops the API from starting, and the image health check reads the database (`/ready`). The backup files are private to the user who runs the backup. The Caddyfile no longer publishes the API unless you turn it on. The quick demo sets the sign in hint at build time and names the demo password. Docs 13 and 14 and `SECURITY.md` now say what the code does about narrowest tag, early stops, self approval and when a language model is called.
- **Third review: setting a source back.** Setting a source back to `company` no longer writes back the tag saved at the first restriction. It gives each row the tag its file or header says, only to rows that still hold the tag the restriction gave them: a file narrowed to `people` while the source was restricted, or a transcript imported again as `people`, stays closed, and the tasks, decisions and passages follow. Rows made while the source was restricted get their own tag back. Documents are marked as changed at the restore, so the next read works each tag out again from the file.
- **Third review: removed meetings.** A meeting the recorder or transcript folder no longer returns is removed after a read that saw everything: the transcript, its indexed text, the decisions and the proposed or rejected tasks go, an approved task stays without its quote, and the weekly reviews, process evidence and stored answers that may quote it are cleared. A read that may not have seen everything (a link, a file that is too large, Fireflies returning a full page of 50) removes nothing, and a pasted in transcript is never removed by it. A Slack day file that cannot be read keeps its old copy.
- **Third review: approvals.** Deciding an approval about tasks the person may not see answers exactly like a missing one. A send approval lists every recipient with the exact subject and text, flags an address outside the company, and is refused when a person, an address or a text changed after it was asked for. Task owners must have an address on `ALLOWED_EMAIL_DOMAINS` (empty: the domains people sign in with), and a reminder is never sent outside them. The audit log hides the entries of an approval the person may not see. A send approval that was already waiting before this change has no fingerprint, so approving it is refused: reject it and ask again.
- **Third review: SOP coverage.** "Covered" and "stale" are worked out from the SOPs the person may read (also in the overview count and the company weekly review), so they no longer show that a restricted SOP exists.
- **Third review: smaller fixes.** A file may retire another with `supersedes:` only from the same folder or above. A folder tag file that is a link, larger than 64 KB or unreadable makes its folder owner only and is named on the Sources page. Importing a transcript again without naming a tag keeps its tag. The integration test is one light request per adapter, not a full read. A person may hold 5 live streams, streams close when their session ends, and signing out ends the token on this server. The web proxy checks the path (dots, encoded dots and slashes, query marks, backslashes) with unit tests. The tools work with a plain `python3` on a fresh clone and say which library is missing. `SESSION_SECRET` is no longer to be set on Vercel (the web app never reads it).
- **Third review: docs.** Commands use `.venv/bin/python`, the Vercel proxy guidance says what each `FORWARDED_ALLOW_IPS` choice means, the Hetzner steps say how to hash the password and how to copy the company folder, the updating guide has a Docker path, and a test fails when a count in the docs, the published schema or the route counts is out of date.
- **Fourth review: meetings are not deleted by a bad answer.** A recorder reply that is not the documented shape (an error body, a null list, a swapped key, a page that is not JSON) is now an error and removes nothing, where before an empty answer wiped every meeting with its decisions. A read that returns no meeting at all while meetings exist waits for a second read that agrees, and a drop of more than `MEETINGS_MAX_REMOVALS` (default 5) waits for the owner to press Confirm removal on the Sources page. A transcript folder the app cannot list is an incomplete read, not an empty one. The hourly job keeps going when the recorder answers badly and says so on the source.
- **Fourth review: decisions and tags.** A decision a person confirmed stays when its transcript is renamed or removed, with its source marked as gone. A transcript header is read through a byte order mark, indentation, zero width characters and Windows line ends. Folder tags now count from the knowledge folder, so a source inside a restricted folder (`people/hr`) can no longer be wider than the folder above it, for folders and Slack exports alike. A tag nobody recognises (a typo) is owner only inside a restricted source too, and is counted on the Sources page.
- **Fourth review: email and the Sources page.** `ALLOWED_EMAIL_DOMAINS` is required outside demo mode (no reminder is sent while it is empty), free mail providers are never the default and are reported when listed, and an address with a comma, semicolon, space, angle brackets or a line break is refused, by the check and again by the mail sender. Staff see how many folder tag files could not be read, and only the owner sees which. The Vercel guide, the tool score and a new docs check no longer ask for `SESSION_SECRET` on the web host. `docs/12` names `ENV_FILE`.
